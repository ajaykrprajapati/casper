## 🎬 SCENE 5: The Fixes [2:30 - 4:00]

### **[SCREEN: Side-by-side comparison or split screen]**

**YOU:**

> "Alright, so how did I fix these? Let me walk you through the approach..."

### **FIX #1: Multi-Modification Extraction**

### **[SCREEN: Show new code]**

```python
# OLD
def extract_modification(...) -> Optional[ModificationObject]:
    return modification  # ONE

# NEW
def extract_modifications(...) -> List[ModificationObject]:
    # Handle both array and single object for backward compatibility
    if isinstance(response_data, list):
        modifications_data = response_data
    else:
        modifications_data = [response_data]
    
    # Validate each
    modifications = []
    for mod_data in modifications_data:
        try:
            modification = ModificationObject(**mod_data)
            modifications.append(modification)
        except ValidationError as e:
            logger.warning(f"Skipping invalid: {e}")
    
    return modifications  # ALL
```

**YOU:**

> "First, I changed the return type to a List. But I also made it backward compatible — if the LLM returns a single object, we wrap it. If it returns an array, we use it.
>
> I updated the prompt to explicitly request a JSON array, with examples showing multiple modifications. And I added validation per modification so one bad extraction doesn't kill the whole batch.
>
> Result: 1 modification per review became 3.8 on average. 280% improvement."

### **FIX #2: Quality-Based Selection**

### **[SCREEN: Show selection algorithm]**

```python
def select_best_reviews(reviews, max_reviews=5):
    # Priority 1: Featured reviews
    featured = [r for r in reviews if r.is_featured]
    if featured:
        return sorted(featured, key=lambda r: r.rating, reverse=True)[:max_reviews]
    
    # Priority 2: High-rated (4-5 stars)
    high_rated = [r for r in reviews if r.rating >= 4]
    if high_rated:
        return sorted(high_rated, key=lambda r: r.rating, reverse=True)[:max_reviews]
    
    # Fallback: Top-rated
    return sorted(reviews, key=lambda r: r.rating, reverse=True)[:max_reviews]
```

**YOU:**

> "For the random selection bug, I implemented a priority system. Featured reviews first — these are curated by AllRecipes. Then high-rated reviews. Then fallback to top-rated.
>
> And I process the top 5, not just one. Why? Because one person's tweak might be good, but five expert modifications aggregated together? That's a truly community-enhanced recipe.
>
> Result: 95% featured review selection rate. Deterministic. Consistent."

### **FIX #3: Silent Failure Detection**

### **[SCREEN: Show validation code]**

```python
def apply_edit_robust(edit, recipe_content):
    match, index, score = find_best_match(edit.find, recipe_content)
    
    if not match or score < 0.85:
        logger.warning(f"No match found")
        return recipe_content, None  # Explicit failure
    
    # Use the MATCHED string, not the search term
    if edit.find in match:
        new_line = match.replace(edit.find, edit.replace)
    else:
        new_line = edit.replace  # Full line replacement
    
    recipe_content[index] = new_line
    
    # Validate the change was actually made
    change = ChangeRecord(from_text=match, to_text=new_line, confidence=score)
    
    if change.from_text == change.to_text:
        raise SilentFailureError("No actual change made!")
    
    return recipe_content, change
```

**YOU:**

> "For the silent failure bug, I added three layers of defense.
>
> One: Use the MATCHED string for replacement, not the original search term.
> Two: Validate that from_text and to_text are actually different.
> Three: Return None explicitly on failure rather than claiming success.
>
> I also added confidence scoring so downstream systems know which changes are high-confidence versus uncertain.
>
> Result: 35% silent failures reduced to zero."
